Endpoints Against the Schema

codeintel-api-endpoint-validator scans a codebase for defined API endpoints and validates them against a defined schema, for example OpenAPI or Swagger. It checks each collected endpoint path against the schema paths and their method keys, and flags inconsistencies between the collected endpoints and the schema.

The tool makes no judgement about whether an endpoint is a vulnerability or a misconfiguration.

A code path that does not exist exits 1. Each run logs how many files were scanned and how many endpoints were checked.

Decorators in Six Verbs

The tool detects endpoint definitions written as route, get, post, put, delete, or patch decorators on app, blueprint, router, or similar objects.

How the Checking Is Done

Logbook margin

Files scanned: logged each run.

Endpoints checked: logged each run.

The schema file is loaded as YAML or as JSON according to its ending, and a schema whose top level is not a mapping is refused with that reason given.

Python files only are walked, and endpoints are gathered by pattern matching over the raw text. A decorator shape mentioned inside a string or a comment is collected as if it were live code, and a decorator whose path is built from a variable is missed. The code's own comments accept both errors on the ground that the schema check is the real gate, and this plate repeats that reasoning rather than hiding it.

Each collected path is compared as an exact string.

A Closing Slash Is a Different Path

A route written with a closing slash and a schema path written without one are reported as different.

A path found in the schema is then asked for its method keys, and at least one of them must be among the lower case names get, post, put, delete, patch, options, or head. A schema that writes its methods in capitals will fail that test.

No Judgement About Vulnerabilities

The boundary stands as the tool states it: no judgement about whether an endpoint is a vulnerability or a misconfiguration.
